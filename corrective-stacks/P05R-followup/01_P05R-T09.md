# P05R-T09 — Authorize version reads by the parent Document

Depends on: none beyond baseline and 00_START_HERE.md.
Closes: R01; version-endpoint portion of R10.
Commit prefix: P05R-T09:

## Defect and reproduction

Documents.access.readVersions treats its id as a Document ID. Payload supplies a version ID for version detail. A foreign version ID colliding with a readable local Document ID returns the foreign body.
Observed fixture: foreign Document 5, version 6, readable local Document 6; GET /api/documents/versions/6 returned 200 and the foreign body. Existing regression incorrectly used /api/documents/5/versions.

## Touchpoints

src/collections/Documents.ts; src/lib/authorization/documentAccess.ts; src/lib/authorization/accessBoundary.test.ts.
Inspect installed Payload findVersionByID/findVersions operations and REST endpoints before choosing the access implementation. Do not assume the same access argument shape for list and detail.

## Required patch

1. Distinguish Document ID and version ID in helper names/types and resolve a requested version's parent before making the existing per-Document read decision.
2. Any internal privileged lookup used for authorization returns no data to the caller until authorization succeeds. Avoid recursive invocation of the same access function.
3. Handle version detail and version listings correctly. Listing must apply authorization before returned documents, pagination, and totals; do not fetch a page, filter afterward, and leak foreign totals or omit authorized results incorrectly.
4. Follow current parent Document readability, including Domain boundary and soft deletion. A historical snapshot's old Domain must not independently grant access.
5. Fail closed on absent/malformed IDs, missing parents, unauthenticated callers, or lookup errors. Preserve the legitimate owner's history access, not an indiscriminate readVersions:false workaround.
6. Exercise actual Payload REST and Local API paths with overrideAccess:false; preserve generated collection mutation closures.

## Required regressions

- Exact numeric-ID collision above, arranged from actual created IDs rather than assuming every fresh DB allocates identically.
- Assert normal foreign Document read is denied and version detail is denied for that same user. Verify no title/body/related metadata is returned.
- Actual GET /api/documents/versions/{versionId}; actual version-list endpoint with foreign and mixed-scope data; Local API findVersionByID and findVersions.
- Authorized owner's detail and list return the expected historical revision; anonymous, missing-parent, and soft-deleted-parent cases fail closed.
- Distinguish authorization failure from a nonexistent endpoint: a positive test on the same endpoint must succeed for the authorized owner.

## Done when

The exploit fails on both interfaces, authorized history still works, no unauthorized list counts leak, and existing security tests remain green. Record the installed API semantics and exact tested URLs in execution-notes/P05R-T09.md.
