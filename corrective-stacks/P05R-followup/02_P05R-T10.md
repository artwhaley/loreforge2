# P05R-T10 — Complete the creation transaction and preserve independent locks

Depends on: T09.
Closes: R02, R07; rollback/concurrency foundation for R10.
Commit prefix: P05R-T10:

## Defects

The editor creates a successor inside a transaction, then relationships.ts reads it without that transaction and throws NotFound. Collection-hook reads do the same. Required Prepared-by credit is applied after commit. Removing a supersedes edge always unlocks its predecessor, even if independently locked before supersession.

## Touchpoints

src/lib/actions/archive.ts; src/lib/db/transactions.ts; src/lib/documents/relationships.ts, links.ts, provenance.ts; src/collections/Documents.ts, DocumentRelationships.ts and link/provenance hooks; src/components/documents/NewDocumentForm.tsx; src/lib/documents/supersession.test.ts.

## Required patch

1. Make one production document-creation unit callable by the editor action and integration tests. This may be an extracted service, but the editor must actually use it; do not create a test-only alternative.
2. Preflight server authorization, selected Domain, destination, type, active Character membership, predecessor eligibility, and submitted link inputs. Preserve the current owner/user-path exception under CC-2026-09-03-05 pending owner confirmation; do not broaden it.
3. Open one real transaction for the aggregate. Propagate its request/transaction context into successor creation, all hook/service reads, edge creation, predecessor lock, required acting-Character Prepared-by link, submitted accepted concerns/tags, and corresponding provenance. Do not commit the record then attempt mandatory attribution afterward. Apply the required-credit guarantee to all existing Character-authored create entry points, including non-superseding and import paths.
4. Existing concerns/free-typed Character creation in this operation must not leave partial accepted metadata or an orphan Character if the aggregate fails. Reuse current semantics; no additional picker or new product feature.
5. Shared runInTransaction must require a genuine transaction ID, join an existing transaction without committing it prematurely, and propagate failure. Remove its sequential/fabricated-ID fallback. Preserve diagnostic evidence if rollback itself fails.
6. Preserve prior lock state using explicit server-written transition metadata, preferably on the supersedes edge with the prior lifecycle and whether this operation applied the lock. Do not infer that every Locked predecessor was locked by supersession. Avoid new user-editable fields.
7. Correction removes the edge and records both timelines atomically. Originally Filed -> Locked -> corrected returns Filed. Originally Locked remains Locked. Restore only a lock owned by this supersession; do not undo a later independent lifecycle decision.
8. For legacy edges whose lock ownership cannot be proven from stored history, preserve Locked conservatively. Document this policy and expose existing safe correction feedback if necessary; never guess an unlock. Queue schema/backfill needs for T14.
9. Catch expected transaction/validation conflicts at the action boundary and return safe error state plus ALL submitted fields: title, body, type, destination, concerns including per-chip relationships/free text, tags, predecessor, and any other existing field. Keep successful Next redirect outside generic catches or rethrow redirect signals properly. No raw DB error/stack in customer output.

## Required regressions

- New successor and its edge are created in the SAME production transaction, including newly created row reads from collection hooks; happy path fully commits.
- Inject failure after successor creation, edge creation, actual predecessor update, required credit, concerns/tags, and provenance. Compare complete before/after state: no orphan successor, edge, credit, Character, provenance, or changed predecessor.
- Character-authored ordinary creation/import cannot commit without required attribution.
- Draft/pending predecessor rejected before writes; unauthorized member rejected with no new record.
- Correction for originally Filed, originally Locked, legacy-unknown lock provenance, and repeated correction.
- Failure returns preserved form values and does not navigate to a success page.
- T15 must add genuine overlapping requests using this same production unit, not precommitted candidate documents.

## Done when

The previously failing create-then-relate reproduction succeeds, all fault cases restore prior state, required credits are transactional, and correction preserves independent locks. Record explicit transaction propagation and new schema requirements in execution-notes/P05R-T10.md.
