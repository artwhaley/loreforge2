## Defect

At review, the actual .env database sl-civic-archive.db lacked folders.public_access, domain_audit_events, and relationship unique indexes; documents.folder_id remained nullable. npm run dev sets PAYLOAD_PUSH=false. Fresh test DB success does not upgrade this database.

## Touchpoints

src/payload.config.ts; schemas/types from earlier tickets; existing migration tooling under src/scripts; package.json; README.md. Add one named, repeatable additive upgrade command and a read-only schema verification command. Do not substitute a fixture reset.

## Required workflow

1. Resolve the configured database URI to its exact path; inventory live server/writers, schema and migration history. Never print secrets. Produce a read-only preflight of required changes, row counts, null destinations, duplicate rule identities, and invalid/forked supersession edges.
2. Detect unexpected backend/path/schema rather than guessing. For remote/production targets stop for explicit direction; this ticket targets the existing local development database only.
3. Prepare a consistent, timestamped backup using SQLite backup facilities or a verified quiescent checkpoint/close procedure including WAL state. Merely copying a live main .db file is not a valid backup. Verify backup can open, passes integrity_check, and matches captured counts. Record its exact location locally; do not commit it.
4. Implement a versioned, repeatable migration; test it on a copy of an old-schema populated DB first. Plan the complete adapter table/index/join structure, not only the obvious audit table columns. Generated types must agree with the resulting schema.
5. Add/backfill Folder publicAccess to inherit; add the audit facility and required relationship/index tables; apply one-source/one-target supersedes constraints; make Document destinations truly required; backfill T11 rule identities and their storage uniqueness; include T10 lock-origin metadata.
6. Existing null-folder rows may be assigned only to a verified root of their known Domain. Unknown Domain/destination is a preflight blocker. Duplicate same-state rule consolidation must preserve equivalent meaning and record survivor/removed IDs. Conflicting rule states or supersession forks/cycles require explicit owner resolution; never choose permission policy, erase a record, or silently drop an edge.
7. Legacy supersession lock ownership follows T10: prove from history or conservatively keep Locked. Never manufacture a prior lifecycle.
8. Do not invent historical audits for past operations. Record the upgrade and any verified repair truthfully as migration evidence using the established approach.
9. After successful dry run, stop/quiesce actual writers, create/verify a fresh backup, and apply to the actual configured local DB. Use transactions where supported, plus a tested restore procedure for nontransactional DDL. Failures must leave the original available, not a half-upgraded running service.
10. Re-run migration: no new changes, duplicated audit rows, or regenerated identities. Run integrity_check/foreign_key_check and verify exact required indexes/constraints, not just column presence.
11. Compare actual before/after document/user/character/membership/role/media counts, record content fingerprints, IDs, and relationship integrity. Only explicitly listed safe backfills/consolidations may differ. No seed run, reset, record deletion, or media modification.
12. Document clone/startup/upgrade/rollback commands accurately in README. Keep normal dev auto-push disabled; do not solve this by globally enabling schema push against arbitrary databases.
