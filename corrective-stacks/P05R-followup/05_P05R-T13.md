# P05R-T13 — Exhaustive Domain-removal cleanup

Depends on: T12.
Closes: R06.
Commit prefix: P05R-T13:

## Defect

deactivateDomainParticipation reads only 500 roles/assignments/Folder rules, with a Domain-wide rule fetch followed by in-memory Character filtering. A 504-rule fixture left four rules behind and recorded completion.

## Touchpoints

src/lib/domains/deactivateDomainParticipation.ts; src/collections/DomainMemberships.ts; src/app/(payload)/api/domain-memberships/route.ts; src/lib/domains/domainRemoval.test.ts; any shared target enumeration used by T12 Role archival.

## Required patch

1. Membership state change, all targeted RoleAssignment revocations, all direct Character Folder-rule removals, and durable audit remain one real transaction.
2. Scope queries to the actual Domain and Character wherever supported. Resolve polymorphic queries using verified adapter syntax or T11 canonical identity/scalars; if a fallback scan is necessary, exhaust every page.
3. Remove correctness dependence on hard limits in Role, assignment, and rule enumeration. Use stable keyset/chunking or complete non-paginated queries as appropriate. Do not page by offset through a result set while deleting earlier rows and thereby skip later matches.
4. Remove inactive as well as active stored assignments where necessary to ensure re-addition cannot resurrect a prior job; preserve historical evidence in audit, not in a reusable assignment. Do not remove assignments or rules belonging to another Domain or Character.
5. Include rules to valid target resources regardless of where they occur in query ordering. Do not confuse role-default rules with the departing Character's direct rules.
6. Hook and sanctioned route call the same production service. A final success audit describes the complete affected set/count, never just the first page. If a postcondition finds targeted rows remain, rollback instead of returning success.
7. If membership deactivation can overlap sanctioned assignment/grant operations, ensure the writer validates active membership inside its transaction and cannot recreate stale permissions after deactivation commits. Preserve the requirement that re-addition starts empty.

## Required regressions

- At least 504 direct rules for one Character; zero remain after success.
- More than 500 mixed Character rules with all target rows outside the initial page.
- More than 500 Domain Roles with a target assignment beyond the first Role page; more than one assignment page if supported.
- Preserve unrelated Character/Domain rules and Role defaults; re-add does not restore roles or direct rules.
- Inject failure in a later cleanup batch and at final audit: membership, assignments, rules, and audit exactly roll back.
- Exercise both the DomainMembership hook and sanctioned route, not only a standalone helper.
- Verify an overlapping grant/assignment cannot leave a removed Character with new direct participation state.

## Done when

Cleanup is complete at arbitrary fixture sizes, one audit describes it, and rollback remains complete across all batches. This fixes current mutation correctness; do not implement the Phase 12 search/UI pagination project. Record count evidence in execution-notes/P05R-T13.md.
