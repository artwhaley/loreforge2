## Result

The discovery step now emits three deterministic artifacts: generated key/type guards, a pure-data catalog sourced only from manifest metadata, and a static-import registry sourced from manifest entrypoints. The legacy `catalog.ts` and `registry.ts` paths are thin re-export facades, so existing callers retain their imports without a hand-maintained Design row/import. Generated catalog thumbnails use the bundled `/design-assets/<key>/...` namespace.

The existing Site Studio selector order is preserved with manifest `sortOrder` values `10/20/30/40` for Civic/Ledger/Poster/Obsidian. Unordered future Designs append deterministically by key; duplicate sort orders fail discovery. This avoids a hidden hard-coded key list and avoids changing established production selector behavior.
