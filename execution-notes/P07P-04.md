# P07P-04 — Detail, history, APIs, and mutation boundaries

Status: complete for the current Phase 7 acceptance surface (2026-09-04).

REST document access now carries the selected acting Character cookie into the
collection boundary. `canAccessDocument` validates controller ownership and
active Domain membership, and maps `update` to `edit_document` instead of
reusing a read scope. The previous controlled-Character union fallback is
gone; a missing active Character receives only true User-level authority.

Document detail loads the current record first, then fetches only ID-level
relationship rows and minimum linked projections. Related titles/credits are
rendered only after the same session read decision; hidden successors,
predecessors, IDs, and bodies are not disclosed. Version-list authorization
uses the authorized parent predicate and preserves the separate version-ID
namespace. Mutation routes continue to use fresh transaction-aware checks and
durable actor-aware audit/provenance.

The live HTTP verification script passes 104 checks after the Records-search
projection checks were added. The isolated real-fixture suite passes all seven
scenarios.
