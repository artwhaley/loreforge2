# P07P-05 — Complete server search and paged Records/People

Status: complete (2026-09-04).

`/api/records-search` now applies the server-owned A/G/D predicate, folder and
descendant selection, type filtering, and parameterized title/body substring
matching before returning a metadata-only projection. It has no 100/500 row
cap, never serializes bodies, and closes readable supersession chains in
bind-safe batches while filtering hidden linked nodes. RecordsExplorer debounces
200 ms, aborts stale requests, and merges returned chain edges without stale
actor results. The response returns 50 distinct supersession groups per opaque
`(updatedAt, id)` cursor; the explorer appends the next page as the records pane
approaches its scroll boundary and resets the cursor when the search scope or
exposed type changes.

People search authorizes before searching, scopes memberships/Characters,
Departments, Roles, contexts, and active assignments to the selected Domain,
chunks Character/assignment IDs, excludes email/SL identity from ranking, and
keeps the visible 25-result interaction bound with stable ID tie-breaking.

Verification includes HTTP authorized/denied search checks and the existing
privacy and People workspace tests. Optional FTS/trigram work is deliberately
not added: no measurement showed LIKE/indexes to be the reported bottleneck.
