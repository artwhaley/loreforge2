# P07X-T02 — acting-identity authorization split + shell behavior

**Branch:** `phase-07x-acting-identity-document-workflows`

## What changed

Authority in ordinary Domain record authorization is now driven **entirely by the acting identity** (the selected Character), never by ambient User-level flags:

- `src/lib/authz/session.ts` — `loadFacts` authority resolution reworked: `domain_admin` whose `administrativeDomain` equals the selected Domain → full Domain operational authority (`admin`); Personal-Domain owner Character → `personal-owner`; `platform_admin` / `player` / `npc` / **no Character** → **no** Domain authority. `platform`/`owner` authority kinds are now unreachable inside Domain decisions — platform work goes through the new seam.
- `src/lib/authz/platform.ts` — new `authorizePlatformOperation` seam: only a validated `platform_admin` Character (or an explicit `allowSystemCreate`-style context) can pass; Domain admins and ordinary identities fail closed.
- `src/lib/characters/identitySelect.ts` — `actingIdentity` / `identityScope` helpers used by the tenant resolver.
- `src/lib/tenant/activeTenant.ts` + `queries.ts` — context resolution and tenant projection now keyed to the validated acting identity; the resolver fails closed on forged/stale Character ids.
- `src/app/(payload)/api/switch-character/route.ts` — validates the target Character (active, controlled by caller, kind-aware) before setting the selector cookie.
- `src/lib/tenant/characterDomains.ts` — Domain projection restricted to the acting Character's active memberships plus provisioned `domain_admin` scope (one Domain).
- `src/app/(frontend)/page.tsx` — dashboard renders against the acting identity.
- `src/collections/Documents.ts` — the create gate now requires an authoring context (acting Character, or the Domain owner User as the sole no-Character create path); Prepared-by credits are validated against an active controlled Character in the Domain, with the provisioned `domain_admin` allowed without RP membership. Direct REST reads/updates fail closed with no acting Character (comment updated).
- `src/lib/actions/archive.ts` + `src/lib/authorization/documentAccess.ts` — authoring contexts carry the acting identity; no ambient user bypass.
- `src/lib/characters/kinds.ts` — controller/scope validation helpers shared with the switch route.
- Tests: `src/lib/authz/phase7xIdentityAcceptance.test.ts` (new, 8 cases — identity authority matrix, platform seam, forged/stale ids fail closed, legacy domain-admins rows don't authorize a different acting Character); `src/lib/authz/phase7Acceptance.test.ts` and `src/lib/documents/workflow.test.ts` updated to the frozen semantics (no-Character callers fail closed; owner authority passes only through the provisioned `domain_admin` Character).
- `package.json` — `test:p07x-t02` script.
