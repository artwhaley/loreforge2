# P08X-T07 — Lifecycle-aware creation and transitions

**Commit:** `P08X-T07 add lifecycle-aware creation and stage-driven transitions`

## What was built

### Creation phase dropdown (`records/new` + both generation paths)
- **`creationStageOptions(session, typeId)`** (`src/lib/authz/session.ts`): pure
  helper returning the ordered creatable stages (Draft → Submitted → Filed) —
  enabled + `allowOnCreation` + effective stage-write permission (Domain
  authority bypasses the write list). The create screen renders the
  starting-phase dropdown only when a Type offers ≥ 2 options; a single option
  means direct-file behavior with no dropdown; zero options keeps the legacy
  filing-policy path (Types without stage configuration).
- **`records/new`** loads one authorization session and passes the per-Type
  options to `NewDocumentForm`, which shows the dropdown, defaults to the
  **latest permitted stage**, and resets on Type change. Failed-server-action
  hydration carries the chosen phase.
- **`prepareDocumentCreation`** now validates the requested lifecycle
  server-side (forged values cannot bypass): the stage must be enabled and
  `allowOnCreation`, the actor must hold stage-write (or Domain authority),
  and the **initial Folder comes from the stage row** — never a caller value.
  The plan exposes `availableCreationStages`. `archive.ts` reads the form's
  `lifecycle` field and falls back to the legacy filing-policy lifecycle only
  when the form sends none.
- **`applyLifecycleStageConfig` merge fix**: partial updates no longer clobber
  `enabled`/`allowOnCreation` when omitted — the documented merge contract now
  holds (only the fields a caller sends are written).

### Stage-driven transitions (`src/lib/documents/workflow.ts`)
- New operations **`deprecate`** (filed → deprecated, event `deprecated`) and
  **`restore`** (deprecated → filed, event `restored`); the workflow action
  seam accepts them and lands back on the record page.
- Authorization: deprecate composes the frozen capability set with
  `manage(deprecated)` (no frozen deprecate capability exists); restore uses
  `restore_document` against the destination (Filed) stage. `stageManageGrant`
  now honors Domain authority so administrators can always deprecate.
- **Disabled stages block transitions through them** — a Type with stage
  configuration refuses moves into (or out of) a disabled stage.
- **Destination folders come from stage config**: the destination stage row's
  Folder wins; legacy route fields remain fallback only.
- Transitions between enabled stages relocate the record atomically and record
  provenance (`priorFolderId`/`routedFolderId`/`reason: lifecycle-route`).

### Document page + vocabulary sweep
- The document detail page now threads `documentTypeId`, the deciding stage
  (current lifecycle), and the private-draft boundary into its decision
  targets — stage-list grants and the creator-only gate apply there exactly as
  in the evaluator and records list (this was a T06 integration gap). Stage-
  move affordances (Submit/File/Approve/Restore) evaluate against the
  **destination** stage, matching the enforcement seam, and the page gains
  **Deprecate** (filed) and **Restore** (deprecated) buttons.
- Review queue and Work page: "Pending records" → "Submitted records";
  "Pending review folder" legacy label re-labeled; home-page recent-records
  filter now applies the private-draft boundary (another T06 list-surface gap).

## Tests (`src/lib/documents/lifecycleTransitions.test.ts`, 9/9 green)

1. Creation-phase options: writable allowOnCreation stages only, ordered, with
   the latest as the default; no writable stage → no option.
2. Direct-file Types yield exactly one option — no dropdown.
3. Creation routes the initial Folder from the stage row (Draft vs Filed).
4. Create at a stage that is not `allowOnCreation` refused server-side (incl.
   a disabled stage even for Domain administration).
5. Create at a writable stage without stage permission refused despite a Type
   grant; Domain administration still passes.
6. A transition between enabled stages relocates to the stage folder and
   records `filed` provenance with prior/routed Folder context.
7. Deprecate moves to the Deprecated folder and records `deprecated`.
8. Restore returns to Filed and its folder, recording `restored`.
9. A transition into a disabled stage is refused (Deprecated seeded disabled).

Unit additions in `workflow.test.ts`: deprecate/restore append the right
provenance events through the pure seam.
