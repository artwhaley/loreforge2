# P08X-T03 — Document Type folder-tree management surface

## What landed

- **`src/lib/documents/typeTree.ts`** — `resolveTypeTree(payload, domainId)`: the
  tree resolver. Every active Department renders as a root at all times
  (name-ordered); manual `type-folders` nest by parent under their Department
  root; Document Types hang under their manual folder when set, else their
  Department root. Types with a null or archived Department surface under the
  virtual **Unassigned** root, which renders only when populated and is never a
  drop target or picker choice. The line-card template is *derived* — the
  active child template of the selected kind (Blank → none); never stored twice.
- **`src/lib/actions/documentTypes.ts`** — audited server actions under
  `manage_types_tags` at Domain: `createTypeAction` (seeds lifecycle-stage rows
  via `ensureLifecycleStageRows`), `updateTypeAction`, `moveTypeAction`,
  `setActiveTypeAction`, `deleteTypeAction` (refused with `has-documents` when
  the type still has Documents — deactivate instead).
- **`src/lib/actions/typeFolders.ts`** — `createTypeFolderAction`,
  `renameTypeFolderAction`, `moveTypeFolderAction`, `deleteTypeFolderAction`
  (refused `not-empty` when subfolders or Types remain).
- **`src/components/documentTypes/`** — `TypeTree.tsx` (toolbar, search,
  context menus, create-type/create-folder/delete-folder/move-folder dialogs,
  template-type popover, drag-and-drop handling, capped `TREE_HEIGHT` of 420),
  `ArboristTypeTree.tsx` (react-arborist `Tree` with the FolderManager visual
  language: guides, chevrons, line cards, drop cursor, cycle guards),
  `DocumentTypesBrowser.tsx` (client shell holding the shared selected-type
  state — the T04 inspector panel joins it), `TypeTree.module.scss`.
- **Page rewrite** — `/domain/[slug]/document-types/page.tsx` now renders the
  tree surface; the flat legacy list is gone. Sub-nav and heading unchanged
  (T01).
- **Department restore** — the Departments API gains an `action=restore` branch
  (`publicListing: true`, same `manage_subdomain` gate as archive) and the
  manage page swaps Archive ↔ Restore with hovertext, so archiving is never
  one-way and Unassigned types can return to a normal root.

## Tests

- New `src/lib/documents/typeTree.test.ts` (DB-backed, `npm run test:p08x-t03`,
  fresh `p08x-t03-test.db`): active roots always render (even empty); Unassigned
  hidden when empty / visible with archived-department types / hidden again
  after restore; manual subfolders nest and carry types; template derivation
  per kind with inactive children ignored; archived type-folders ride into
  Unassigned; null-department types degrade to Unassigned; inactive flag on the
  leaf.
- `npx tsc --noEmit` green; full `npm test` 129/129 green.

## Notes / decisions

- Duplicate is deliberately absent from the right-click menu until T05 (per the
  ticket).
- The type tree is navigation/organization only — it never moves archive
  Documents.
- Action-level guards (delete refusal, `not-empty` folder delete, cycle
  guards) live in the server-action seams; the UI enforces them too, and the
  DB-backed resolver tests cover the placement logic those guards protect.
