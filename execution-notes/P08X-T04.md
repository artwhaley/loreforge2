# P08X-T04 — Inspector panel: identity, template section, lifecycle table

**Commit:** `P08X-T04 add Document Type inspector panel and lifecycle configuration`

## What was built

The shared create/edit surface beneath the type tree (`TypeInspector.tsx`), opened
in create mode by "Create new" and in edit mode when a Type is selected
(`DocumentTypesBrowser.tsx` wires tree + inspector over one selection state).

### Identity
- Name / Description / Active checkbox with Active/Inactive badge (hovertext on
  all three).

### Placement
- Required Department picker (defaults to the current tree selection's
  department) — never Unassigned by choice; optional manual subfolder picker
  derived from the resolved tree (department-filtered, indented by depth).

### Template section
- Three-option selector: Blank Document / Markdown Template / Form Template
  writing `templateSelection` (segmented control with per-option hovertext).
- Edit links for the chosen kind when a constructed child exists
  (`/domain/…/templates/:id/edit` or `/domain/…/forms/:id/edit`).
- "Create [kind]" scaffold action (`scaffoldTypeTemplateAction`) when the chosen
  kind has no constructed template yet — creates the single default child
  (Markdown body template, or a minimal Form with one content field), placing it
  in the first enabled stage Folder (draft→submitted→filed), else the legacy
  draft/default folder, else the Domain's system root.
- Switching kinds never touches the other kind's constructed template
  (persistence by construction — T05 tests the duplicate half).

### Lifecycle table
- Four rows (Draft / Submitted / Filed / Deprecated), each with the "Part of
  this Type's lifecycle" checkbox that greys/disables the rest of the row.
- "Allow on creation" checkbox (enabled rows only).
- Stage folder cell: current folder name button opening the **compressed
  arborist folder-navigation popup** (~480px dialog, ~280px tree, static
  single-select with Use/No folder/Cancel) — `FolderPickerPopup.tsx` +
  `ArboristFolderPicker.tsx`, same visual language as the Folders screen.
- Read / Write / Edit others / Manage cells with chip-style role-list editors
  (`RoleListEditor.tsx`, multi-select of Domain roles, hovertext definitions).
- Hovertext on every control (per-option, per-checkbox, per-cell titles).
- **P08REG-01 supersedes parts of this note:** the Placement section heading
  and explanation are removed (fields live in the identity section); the
  lifecycle table is a one-line-per-stage grid with a header row; the Draft
  row's "Private drafts allowed" checkbox is removed (private drafts are
  always allowed).

## Lib / actions

- `lifecycleStages.ts`: `applyLifecycleStageConfig` — upserts the four rows,
  validates ≥1 enabled stage, unknown stages, same-Domain folders and role
  lists (readable errors, not hook rejects); partial configs update only the
  fields they carry so e.g. a folder-only change never clobbers role lists.
- `typeTree.ts`: `TypeTreeLeaf` gains `constructedTemplates` (active child per
  kind, never just the selected one); new `resolveInspectorData` (Domain roles,
  Folder tree for the popup, stage rows grouped by Type).
- `documentTypes.ts` actions: `createTypeAction`/`updateTypeAction` accept the
  full lifecycle config + `templateSelection`; new `scaffoldTypeTemplateAction`.

## Tests (`src/lib/documents/lifecycleStages.test.ts`, 6/6 green)

- Fresh-Type seed: four rows, Draft+Filed enabled, Draft allow-on-creation +
  private-drafts on, Submitted/Deprecated disabled.
- Full table save/load round trip incl. role lists and folders.
- Partial config updates only touched fields (role lists survive a folder move).
- Validation failures return readable errors (0 enabled stages, unknown stage,
  cross-Domain folder, cross-Domain role).
- Switching selection never loses the other kind's template; switching back
  restores the exact prior template.
- `resolveInspectorData` returns roles, the Folder tree, and stage rows by Type.
