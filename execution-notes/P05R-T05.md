# P05R-T05 — Domain Participation Removal Transaction and Durable Audit

**Branch:** `phase-05-remediation` · **Commit:** see `git log -1` · **Mode:** DATA-INTEGRITY + AUDIT

## Seam discovery result

No durable administrative audit facility existed. `DocumentProvenanceEvents` is document-scoped and `access`-false, and all Phase 5 admin "audit" was `payload.logger.info` lines. **Created** `DomainAuditEvents` (append-only) plus the `recordDomainAudit` service seam.

## What changed

### A. Atomic deactivation (`src/lib/domains/deactivateDomainParticipation.ts`)
- The cascade (RoleAssignment revoke + direct Folder PermissionRule removal + durable audit) now runs in **one DB transaction**. Called from the `DomainMemberships.afterChange` hook it **joins** the outer operation's transaction via `req.transactionID`, so the membership status flip, the cascade, and the audit event commit or roll back together; called standalone (tests, future sanctioned-route use) it opens its own transaction via `runInTransaction` (moved to shared `src/lib/db/transactions.ts`; `relationships.ts` re-exports it).
- The audit event is the **last** step: a failure anywhere leaves no false "deactivated" record.
- **Evidence — two latent bugs found and fixed in the old cascade:**
  1. The polymorphic `principal: { equals: ... }` query on `permission-rules` throws in Drizzle, and a **thrown find inside a joined transaction calls `killTransaction`, silently rolling back the whole outer transaction** (`payload/dist/collections/operations/find.js:284`). The old service's `.catch(() => ({ docs: [] }))` swallowed the error, so direct Folder rules were **never** actually revoked and the membership flip itself was silently lost. Fixed by querying plain columns (`principalType`/`resourceType`) and filtering principal client-side; a query failure now fails the removal loudly.
  2. Hook-inner joined writes are only safe when no inner op throws — verified empirically that with the query fixed, joined delete/update/create commit and roll back correctly (probe + acceptance tests).
- Test-only seam `simulateFailureAt: 'folderRules'`, forwarded from operation `context.simulateDomainRemovalFailureAt`, proves mid-cascade rollback through the real hook path.

### B. Durable audit seam
- `src/collections/DomainAuditEvents.ts` — append-only (`access` all-false, mirroring DocumentProvenanceEvents); envelope: Domain, eventType, timestamp, actorUser, actorCharacter, targetType, targetId, action, server-generated structured `context`. Vocabulary: `membership_changed`, `role_changed` (incl. creation/update — added per ticket delta), `role_assignment_changed`, `folder_access_changed`, `permission_rule_changed`. Composite index `(domain, targetType, targetId)`.
- `src/lib/domains/domainAudit.ts` — sole writer (`recordDomainAudit`), optional `transactionID` join, context never client-supplied.

### C. Sanctioned routes now audit
- `domain-memberships` route: additions/reinstatements audited (`added`/`reinstated`); removals audited by the transactional cascade (exactly one coherent event).
- `roles` route: `created` / `archived` (Role definitions are administration truth).
- `role-assignments` route: `assigned` / `removed`.
- `permission-rules` route (the People-workspace Folder-access editor): `folder_access_changed` with server-generated state context.
- Route post-hoc audit writes are best-effort (`logger.error` on failure); the removal cascade audit is authoritative (in-tx).

## Automated acceptance evidence

New suite `src/lib/domains/domainRemoval.test.ts` (6 tests, run via `test:security` chain with a fresh DB):
- **Failure injection through the hook** (`context.simulateDomainRemovalFailureAt = 'folderRules'`): the update rejects; membership still `active`, RoleAssignment and Folder rule intact, **zero** deactivated audit events; unrelated Domain untouched.
- **Standalone service failure injection**: same guarantees on the direct service path.
- **Successful removal**: membership `inactive`, assignment and direct Folder rule revoked, **exactly one** durable `membership_changed/deactivated` event with actor, target membership id, and `removedRoleAssignmentIds`/`removedFolderRuleIds` in context; unrelated Domain and its audit silence untouched.
- **Re-add starts clean**: membership re-activated, a fresh RoleAssignment succeeds.
- **Route audits**: role create → `role_changed/created`; assignment → `role_assignment_changed/assigned`; Folder access → `folder_access_changed`; membership add/remove → `membership_changed/added` and `deactivated`.
- **Append-only**: ordinary users can neither read nor write `domain-audit-events`.

Full runs: `npm test` 78/78 · `npm run test:security` 25/25 (4 access-boundary + 10 supersession + 5 people-workspace + 6 domain-removal) · `tsc --noEmit` clean · packet validation PASS.
