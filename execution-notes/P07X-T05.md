# P07X-T05 — Document-Type lifecycle Folder routing

Status: complete (`<commit>`)

## What shipped

- **DocumentTypes routing fields**: `draftFolder`, `pendingReviewFolder`,
  `filedFolder`, `lockedFolder` (relationships to folders), alongside the
  existing `defaultFolder` which serves as the fallback route. Multiple
  lifecycle states may target the same Folder.
- **Hook invariant**: every configured route Folder (default + four states)
  must belong to the Type's Domain — a cross-Domain route is rejected.
- **Centralized routing helper** (`src/lib/documents/typeRouting.ts`):
  `resolveLifecycleRouteFolder(type, lifecycle, currentFolderId)` —
  state Folder wins, `defaultFolder` is the fallback, and a record with
  neither keeps its current Folder (legacy Domains without routing config
  stay put). Pure function, unit-tested.
- **All lifecycle transitions wired** (`transitionDocument`): submit,
  file, approve, reject, lock, unlock each resolve the destination Folder
  server-side and land lifecycle + Folder relocation in ONE update
  (atomic). Provenance context records `priorFolderId`, `routedFolderId`,
  and `reason: 'lifecycle-route'` when a move occurs.
- **No caller-supplied destination**: the workflow service/action accept no
  destination; planted `folder`/`destination` inputs are ignored (tested).
- **Incident Report fixture** in `seed/phase7Acceptance.ts`: Plain Text Type
  routes draft → Incident Reports, pending_review → Pending Incident
  Reports, filed → Investigating Incident Reports, locked → Closed Incident
  Reports (new Folders under the Incident Reports branch).
- **T04 projection interplay**: routing moves are real Folder relocations,
  so the permission-aware projection picks routed Folders up through their
  Documents automatically.
