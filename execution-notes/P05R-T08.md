## Fixes

### 1. Soft-delete authorization bypass (review #2, HIGH)

`softDeleteDocumentAction` skipped the interim boundary whenever the actor had
an active Character, letting any domain member soft-delete any record (delete
is not a Character-scoped action; restore always enforced the check — the
asymmetry confirmed the bug).

- `src/lib/actions/documentWorkflow.ts`: delete now requires
  `requireInterimWorkflowAuthority` unconditionally, mirroring restore.
- `src/app/(frontend)/domain/[slug]/documents/[id]/page.tsx`: the Delete
  control and the "Create superseding document" link render only for
  `role === 'admin'` (the same owner/operational-admin set the server enforces;
  supersede already rejected non-admins cleanly server-side since P05R-T02).
- `src/app/(frontend)/domain/[slug]/records/RecordsExplorer.tsx` +
  `records/page.tsx`: new `canDeleteRecords` prop (was: Delete enabled for any
  signed-in user) disables Delete for non-admins in the toolbar and context
  menu.
- `src/lib/authorization/interim.ts`: scrubbed customer-visible process
  language ("during Phase 3") from the deny message.

### 2. Lint repaired (review #2, HIGH)

`eslint.config.mjs` spread `nextPlugin.configs['core-web-vitals']`, but
eslint-config-next@16 exports flat configs (the preset is the
`eslint-config-next/core-web-vitals` subpath export), so lint could never load.
- Config rewritten for the flat-config preset; `lint` npm script added.
- Burned down all 16 errors + 2 meaningful warnings across the tree:

- Remaining: 2 `@next/next/no-img-element` warnings in TenantShell — deliberate

  Result: `npx eslint .` → 0 errors, 2 warnings.

### 3. .gitattributes / CRLF (review #2, HIGH for future executors)

No `.gitattributes` existed; with global `core.autocrlf=true` the packet's
byte-integrity contract (SHA256SUMS + validate_packet.py) failed in any fresh
Windows clone (4 files were CRLF in this very checkout). Added
`.gitattributes` pinning `eol=lf` for `LoreForge_Execution_Packet/**` and
`execution-notes/**`, normalized the tree to LF, and regenerated SHA256SUMS
(128 authoritative entries) → **PACKET VALIDATION: PASS**.
- Archive safety: `*.zip binary -eol` (rule order matters — the packet `eol=lf`
  rule would otherwise re-enable text filtering; a zip whose header lacks NUL
  bytes is misdetected as text). Verified the committed zip is byte-identical
  to its HEAD blob and unzips cleanly (95 members).

- `DEF-PREP-01` — add-more-Prepared-by-credits control (rendering exists).
