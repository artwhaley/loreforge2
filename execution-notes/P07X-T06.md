# P07X-T06 — Type-first New Document and three creation methods

Status: complete

## What shipped

- Added `allowBlank`, `allowTemplate`, and `allowForm` settings to Document
  Types. Active legacy Types retain blank creation by compatibility default;
  Template/Form methods are effective only when an active child of the matching
  kind is attached.
- Reworked the customer New Document flow to choose an authorized Document
  Type first, then an effective Blank, Document Template, or Form method.
  Ordinary destination Folder selection is removed from the customer surface.
- Blank creation stays in the normal Markdown editor. Document Templates render
  their title/body composition, and Forms render their neutral schema output;
  all three create ordinary Documents retaining the chosen Type and Prepared-by
  semantics.
- Initial lifecycle Folder resolution is Type-owned through the existing
  lifecycle routing helper. Forged or legacy `folderId`/Template destination
  values are ignored by the Type-based create path.
- Form Studio no longer edits a customer destination Folder. Legacy destination
  columns remain for migration compatibility, with Form save/submit paths
  deriving a Type route instead.
- Added non-destructive schema migration support for the new method and route
  columns, seed/migration defaults, and focused creation-method tests.
