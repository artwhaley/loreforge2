# P05R-T03 — People, Roles, Folder Access, and Search Contract Corrections

Status: complete. Commit: `P05R-T03:` (see git log for hash).

## A. Folder access is now truly three-state

`PermissionCheckbox` (checkbox collapsing Inherit+Allow into one checked state,
making a mistaken Deny a one-way ratchet) was replaced with `PermissionAxis` in
`src/components/people/PersonAccessTrees.tsx`: one radiogroup per axis with
`Inherited | Allow | Deny`. The existing sanctioned `/api/permission-rules`
seam is unchanged and already implements the semantics — Inherit deletes the
direct rules; Allow/Deny recreate them — so the Save flow now carries every
state the UI can express. The Role tree and Folder tree stay structurally
separate; Folder saves never touch Role/RoleAssignment rows.

## B. Role filters restored to the contract labels

Role mode is now exactly `held | assignable` with labels "Held roles" and
"Roles I can assign" (`src/lib/people/roleFilters.ts`; the old "All roles /
Held only" is gone). "Roles I can assign" is computed pre-P07 from the interim
authorization via `computeAssignableRoleIds` (`src/lib/people/participation.ts`):

- Domain Owner / operational Domain Admin → every in-Domain Role;
- otherwise → only Roles the actor holds plus same-Department descendants
  beneath those held Roles (no upward or sideways authority; no cross-
  Department grant). P07-T03 replaces this calculation with the evaluator.

The person-workspace page computes `assignable` per Role for the viewing actor
and defaults the filter to `assignable` (query `?roleFilter=held` switches).

## C. People-search keyboard behavior

`PeopleSearch.tsx` now handles ArrowDown/ArrowUp (move the active option),
Enter (open the active Character), and Escape (clear and close), keeps the
active item visible (clamped when results shrink, scrolled into view on move),
and wires correct combobox ↔ listbox ↔ option ARIA (`role=combobox`,
`aria-expanded`, `aria-activedescendant`, `aria-selected`). Mouse behavior is
untouched. The pure step/clamp logic lives in `searchNavigation.ts` and is unit
tested; the component layer only maps keys to it.

## D. Email removed from People search

The `/api/people-search` route no longer includes the controlling account email
in the scored fields/haystack — it was never returned, but it influenced
ranking as a side channel. Search now covers contracted identity fields only
(name, local alias, Department, Role, controller display name). Regression
asserts an email-only query returns nothing and the raw email never appears in
the payload.

## E. Department participation regression

`departmentsForCharacter` derives participation exclusively from active
RoleAssignments joined to Roles — no SubdomainMembership or legacy row is
consulted (the function signature cannot even accept one). The regression test
walks the full lifecycle: no Role → no participation; first Role in a
Department → participation appears; second Role → still present; one removed →
still present; last removed → disappears; inactive rows never grant
participation.

## F. Responsibilities kept separate

Role assignment posts to `/api/role-assignments`; Folder access posts to
`/api/permission-rules`; neither mutates the other's records; DomainMemberships
only change through their own membership flow. Asserted in the tri-state
regression by snapshotting Role and RoleAssignment rows before and after every
Folder-access change.
